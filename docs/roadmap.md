# GoSeed 实施路线

先跑通开发与交付链路，再完善通用管理能力，最后把真实业务样板提炼为脚手架。每阶段以可验证结果结束，不以创建目录数量作为进度。

## 当前交付

第一阶段工程骨架已落地：

- 项目级 ai-context 与 zero-skills 子模块固定到审查提交，AGENTS.md 引用本地资料。
- 单 Go module，go-zero/goctl、protoc/插件与 Node/pnpm 版本固定。
- admin-api、app-api、system-rpc 独立进程；两条 HTTP → RPC 探测链路可运行。
- system 装配 GORM MySQL 连接池和 Redis，区分进程存活与依赖就绪。
- Vue 工作台按 feature 组织，使用生成的 OpenAPI 类型调用真实 API。
- Compose、环境示例、健康探测、统一业务错误、生成验证和 CI 配置已提供。

## 第一阶段 工程骨架（已完成）

验收入口：

- 根 README 包含本地与完整容器两种启动方式。
- `make smoke` 检查两个 API 的存活、依赖就绪、RPC 响应与 Trace ID。
- `make verify-gen` 在临时副本检查重复生成与新增 API/RPC 契约，不覆盖手写实现。
- `make build` 分别构建三个服务与前端；`make check` 检查单模块与 import 边界。

管理员认证与角色授权已在第二阶段接入；事务审计、操作日志查询、字典和系统配置已接入。文件与 Asynq 已在第三阶段接入。

## 第二阶段 系统管理闭环（已完成）

已实现第一批：goose 迁移、幂等管理员初始化、登录与当前用户、refresh token 轮换、退出、修改密码、会话撤销、逐方法 RPC 服务身份校验、登录页和账户安全页。账号禁用可由领域运维命令执行。

已实现第二批：[管理员列表、角色权限和菜单按钮授权](authorization.md)，包含主库版本确认、两实例策略加载、编辑冲突与最后超级管理员并发保护。第三批已接入[操作日志](operation-audit.md)，管理员/角色变更与日志原子提交，提供筛选、历史详情与独立读取权限。第四批已接入[字典和系统配置](system-settings.md)：分类与字典项、普通业务参数、独立权限、revision 冲突与事务审计；侧栏分组可折叠，页签支持右键操作。

实现管理员登录、刷新和退出，用户、角色、权限、菜单、字典、配置以及关键业务审计。完成版本化迁移、bootstrap 和前后端统一权限键。

验收条件：

- 管理员可以登录、配置角色、授权菜单与按钮并完成用户管理。
- 禁用、改密、注销后，新请求不能沿用旧会话；refresh token 轮换可验证。
- 两个 system-rpc 副本同时运行时，权限撤销、通知丢失和实例重启行为符合架构约定。
- 非管理员 token、越权角色分配、直接调用未授权 RPC 均被拒绝。
- 权限目录同步可重复执行，不重置已有角色授权或管理员密码。

## 第三阶段 文件与异步能力（已实现）

已实现[私有文件上传下载](files-and-tasks.md)、本地/S3 兼容存储适配、字典 CSV 导出、system-worker 和 system-scheduler。可靠任务使用事务 outbox、数据库幂等与租约恢复；后台提供任务状态与人工重试。清理计划按 UTC 小时投递，未提供任意 cron 编辑器。

验收条件：

- 文件在多副本环境可访问，未授权用户不能获取私有文件。
- 队列短暂故障、worker 崩溃与重复消息不会丢失已承诺任务，也不会重复产生业务副作用。
- scheduler 更新避免实例重叠，重复投递仍由业务幂等消化。
- 审计与任务排错信息可通过 Trace 或 request ID 关联。

## 第四阶段 业务样板（已实现）与项目模板（待提取）

已实现 [member 会员样板](member-module.md)：C 端账号密码注册、JWT 登录/刷新/退出、个人资料与改密；后台查询会员、查看事件和启停账号。配套独立 RPC、数据库账号、迁移、权限菜单、API client、并发测试和 HTTP 验证。

验收内容：

- API 不访问会员表；member 与 system 使用独立数据库账号。
- 会员与管理员的 JWT、Cookie、会话完全隔离，停用/改密/退出后的新请求拒绝旧会话。
- 后台操作经 system CheckAccess 授权，C 端仅操作当前身份的数据；公开 DTO 不泄露内部字段。
- 并发刷新、唯一账号、revision 冲突和审计故障回滚有测试。
- [模块开发教程](new-module-guide.md) 给出每层实际文件及新增流程。

自动生成完整业务模块、复制第二个新领域、替换 module/品牌的新项目生成器尚未实现，后续根据实际复用情况提取，不将教程等同于生成器。

## 后续按需扩展

| 能力 | 引入条件 |
| --- | --- |
| PostgreSQL | 完成方言迁移、约束与集成测试 |
| 多租户与会员扩展 | 有真实业务规则，身份、授权、查询范围均贯通 |
| etcd 或 Kubernetes | 有多实例发现、调度与运维需求 |
| Kafka 与事件投影 | 有跨域订阅、吞吐量或报表需求 |
| 分布式事务协调器 | 明确的跨域一致性目标无法用本地事务、幂等和补偿满足 |
| embed 交付 | 需要前端随服务二进制分发，且已验证路由与资源更新 |
| 独立 Go module | 团队、依赖或发布周期需要独立版本 |

第一版不实现这些扩展的空接口和配置开关，保留清晰的领域边界即可。
