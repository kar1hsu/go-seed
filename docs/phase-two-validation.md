# 第二阶段：管理员与角色授权验证

验证日期：2026-10-29。本批范围为管理员管理、角色权限、菜单按钮授权；认证功能沿用既有会话实现。

| 检查 | 本地结果 |
| --- | --- |
| `make migrate bootstrap` | 权限表迁移与首次超级管理员关联成功，已有密码未变更 |
| `make check test build` | 模块边界、文档链接、gofmt、vet、前端类型/格式、Go 测试与前后端构建通过 |
| `make verify-gen` | 重复生成一致，追加 API/RPC 契约保留手写实现并可编译 |
| `make test-auth` | MySQL 认证回归通过，含 race |
| `make test-rbac` | 独立临时数据库权限回归通过，含 race |
| `make smoke auth-smoke rbac-smoke` | 真实 Compose 服务的健康链路、认证与管理 HTTP 用例通过 |
| `pnpm --dir web/admin test` | 退出、切换账号、权限快照乱序响应三种前端竞态通过 |
| 浏览器验证 | 管理员/角色表格、超级角色只读权限、只读账户菜单/按钮隐藏、越权路由 403、撤销后禁止访问通过 |

权限集成验证包含分页/筛选、授权依赖、禁止跨越自身权限范围、禁止普通管理员修改自己的角色、停用角色和账户、两实例读取新策略、乐观编辑冲突、最后超级管理员的并发保护、目录重复同步和 bootstrap 不恢复旧关联、数据库不可用时拒绝授权。HTTP 验证还覆盖创建 201、缺少 CSRF、伪造身份头、直接写接口 403、编辑 409 与删除查询参数。

破坏性测试在随机临时库执行，结束后删除测试库；HTTP 与浏览器验收只清理各自创建的临时账户和角色，保留已有管理员与业务数据。数据库凭证、会话 token 和初始密码未加入版本控制。

当前不包含跨领域 CheckAccess、业务审计、动态菜单编辑、字典/配置，以及 Asynq worker/scheduler；这些能力仍按 [实施路线](roadmap.md) 后续接入。
